AlmaLinux OS 9.9, codename Chartreuse Bobcat, was released on November 16, 2026. It ships kernel 5.14.0-741.22.1.el9_9, is compatible with Red Hat Enterprise Linux (RHEL) 9.9, and includes GCC Toolset 16, fapolicyd 2.0, and .NET 11.

## Providing Feedback and Getting Help

Please report any issues you may encounter during tests on the [AlmaLinux Bug Tracker](https://bugs.almalinux.org/). Additionally, if you feel like providing feedback, asking any questions, or talking about all things AlmaLinux, please join [the AlmaLinux Mattermost](https://chat.almalinux.org), [the AlmaLinux forums](https://forums.almalinux.org/c/devel/9-stable/36) and [the AlmaLinux subreddit](https://reddit.com/r/almalinux).

## Changelog

**GCC Toolset 16 arrives in Enterprise Linux 9**, bringing gcc 16.2.1 and binutils 2.46 alongside the existing GCC Toolset 15. LLVM and Rust toolsets move to 22.1.8 and 1.97.1 respectively.

**fapolicyd moves from 1.4.5 to 2.0.1**, a major version rather than a point update. Since the file access policy daemon sits in the execution path of every binary on a hardened system, existing rules and trust databases are worth re-testing before this reaches production.

**authselect no longer merges groups by default.** Group merging in `nsswitch.conf`, introduced in AlmaLinux 9.8, is now opt-in via the `with-group-merging` feature. Systems that rely on local and remote groups being merged need the feature enabled explicitly after the update.

### Deviations from RHEL 9

- AlmaLinux OS continues to carry an earlier backport of the upstream kernel fix [d919a1e79bac](https://github.com/torvalds/linux/commit/d919a1e79bac890421537cf02ae773007bf55e6b) ("proc: fix a dentry lock race between release_task and lookup"), which addresses excessive CPU consumption by `systemd` and `ps` during task cleanup. AlmaLinux originally submitted this fix to the CentOS Stream 9 kernel via [MR !7769](https://gitlab.com/redhat/centos-stream/src/kernel/centos-stream-9/-/merge_requests/7769), but its inclusion upstream was postponed. The [AlmaLinux Engineering Steering Committee (ALESCo)](https://almalinux.org/alesco/) voted to include it in AlmaLinux 9.8 ahead of RHEL, and the 9.9 kernel still applies it, as RHEL 9.9 has not picked the fix up.
- The AlmaLinux OS 9.9 kernel includes security fixes that are not available in the RHEL 9.9 kernel, see [Kernel security fixes not available in RHEL 9.9](#kernel-security-fixes-not-available-in-rhel-9-9) below.

## Installation instructions

There are three installation ISO images available:

`AlmaLinux-9.9-x86_64-boot.iso` - a single network installation CD image that downloads packages over the Internet.

`AlmaLinux-9.9-x86_64-minimal.iso` - a minimal self-containing DVD image that makes possible offline installation.

`AlmaLinux-9.9-x86_64-dvd.iso` - a full installation DVD image that contains mostly all AlmaLinux packages.

Download a suitable ISO image from the 9.9/isos/$arch/ directory, for example:

```bash
$ wget https://repo.almalinux.org/almalinux/9.9/isos/x86_64/AlmaLinux-9.9-x86_64-boot.iso
```

Download and import the AlmaLinux public key:

```bash
$ wget https://repo.almalinux.org/almalinux/RPM-GPG-KEY-AlmaLinux-9
$ gpg --import RPM-GPG-KEY-AlmaLinux
```

Download and verify a checksums list:

```bash
$ wget https://repo.almalinux.org/almalinux/9.9/isos/x86_64/CHECKSUM

# we are looking for "Good signature"
$ gpg --verify CHECKSUM
gpg: Good signature from "AlmaLinux OS 9 <packager@almalinux.org>" [unknown]
gpg: WARNING: This key is not certified with a trusted signature!
gpg:          There is no indication that the signature belongs to the owner.
Primary key fingerprint: BF18 AC28 7617 8908 D6E7  1267 D36C B86C B86B 3716
```

Verify the downloaded ISO image checksum:

```bash
# calculate the downloaded ISO SHA256 checksum
$ sha256sum AlmaLinux-9.9-x86_64-boot.iso

# compare it with expected checksum, it should be the same
$ cat CHECKSUM | grep -E 'SHA256.*AlmaLinux-9.9-x86_64-boot.iso'
```

If you decide to use the `AlmaLinux-9.9-x86_64-boot.iso` image, you may need to provide the `9.9/BaseOS/x86_64/kickstart/` URL repository from the selected mirror as the Installation Source in the event that the installer is not able to find the closest mirror for some reason.

There are no extra Installation Sources required if you decided to go with either the minimal or DVD ISO images.

## Upgrade Instructions

To update your AlmaLinux OS 9 to 9.9 run:

```bash
$ dnf upgrade -y
```

## 9.9 Beta Testers

To update your AlmaLinux OS 9.9 beta to 9.9 stable run:

```bash
$ dnf install https://repo.almalinux.org/almalinux/almalinux-{release,repos,gpg-keys}-latest-9.$(uname -m).rpm
$ dnf upgrade -y
```
